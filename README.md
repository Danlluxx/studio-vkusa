## О проекте

Репозиторий содержит новую версию сайта «Студии Вкуса». Локальная копия прежнего сайта на 1C-Битрикс используется только как источник материалов для миграции и в GitHub не публикуется.

Основная разработка ведётся в [`web/`](web/): это самостоятельное SSR-приложение на Astro с административной панелью и SQLite.

### Возможности

- публичный сайт с меню, форматами мероприятий, фотоотчётами и формой заявки;
- адаптивная административная панель по адресу `/admin/`;
- CRM заявок и роли администратора, менеджера и редактора;
- управление меню, ценами, страницами, отзывами и медиатекой;
- SEO-настройки, sitemap, robots.txt и редиректы;
- собственная аналитика и журнал действий;
- уведомления через Telegram и SMTP;
- резервное копирование SQLite и загруженных файлов.

## Технологии

- [Astro 7](https://astro.build/) в SSR-режиме;
- [Tailwind CSS 4](https://tailwindcss.com/);
- встроенный `node:sqlite`;
- Node.js adapter для production-сервера;
- Node.js-хостинг для текущего технического адреса; nginx и systemd остаются вариантом для собственного VPS.

## Быстрый старт

Потребуется **Node.js 22.23.4 или новее**.

```bash
cd web
npm ci
cp .env.example .env
```

Укажите в `web/.env` пароль первого администратора длиной не менее 10 символов:

```dotenv
ADMIN_LOGIN=admin
ADMIN_PASSWORD=change-this-password
```

Запустите сервер разработки:

```bash
npm run dev
```

- сайт: <http://localhost:4321>
- админ-панель: <http://localhost:4321/admin/>

Первый администратор создаётся только при запуске с базой, в которой ещё нет пользователей. Смена `ADMIN_PASSWORD` после этого не меняет пароль существующей учётной записи.

## Команды

Все команды выполняются из каталога `web/`.

| Команда | Назначение |
| --- | --- |
| `npm run dev` | Запустить локальный сервер разработки |
| `npm run build` | Собрать production-версию |
| `npm start` | Запустить собранное приложение |
| `npm run images` | Обработать изображения из legacy-каталога `www/upload` |
| `node scripts/demo-data.mjs` | Добавить демонстрационные данные |
| `node scripts/demo-data.mjs --clear` | Удалить демонстрационные данные |

Production-проверка локально:

```bash
npm run build
npm start
```

## Данные и конфигурация

Редактируемые данные хранятся отдельно от кода:

- `web/data/site.db` — база SQLite;
- `web/data/uploads/` — загруженные изображения и файлы;
- `web/src/data/*.json` — исходный контент для первичного заполнения;
- `web/static-media/` — подготовленные изображения прежнего сайта.

Перед рискованными изменениями и переносом приложения сохраняйте весь каталог `web/data/`. Не копируйте активную SQLite-базу во время записи: остановите приложение или используйте встроенный механизм резервного копирования.

Доступные переменные окружения описаны в [`web/.env.example`](web/.env.example). Учётные данные администратора, Telegram и SMTP должны находиться только в локальном `.env` или в защищённом файле окружения сервера. Не добавляйте их в Git.

```text

```

Подробности по новой версии и эксплуатации: [`web/README.md`](web/README.md).

## Legacy-версия

Копия старого сайта и дамп базы остаются в локальной рабочей папке и исключены из этого репозитория. Скрипты переноса в `tools/` могут использовать их локально.

## Развёртывание

Текущая техническая версия работает на отдельном Node.js-хостинге:

- адрес: <https://client1.179.252.220.236.sslip.io/>;
- сервер запускает `npm start` и передаёт `PORT=3101`;
- рабочие данные находятся в `project/.npm-cache/studio-vkusa-data/` и не входят в Git;
- детали сборки и обновления описаны в [`web/README.md`](web/README.md).

Порядок подключения основного домена к этому хостингу и задача для администратора публичного proxy описаны в [`deploy/client1-domain.md`](deploy/client1-domain.md).

Для собственного VPS предусмотрен запуск за nginx:

```text
Internet → nginx → 127.0.0.1:4321 → Astro SSR
```

Шаблоны для VPS находятся в [`deploy/`](deploy/):

- `studio-vkusa.service` — systemd-сервис;
- `studio-vkusa.env.example` — production-переменные окружения;
- `nginx.conf.example` — конфигурация reverse proxy;
- `studio-vkusa-backup.*` и `backup.sh` — регулярное резервное копирование.

Ожидаемые пути для этого варианта VPS:

- приложение — `/opt/studio-vkusa/web`;
- постоянные данные — `/var/lib/studio-vkusa`;
- секреты — `/etc/studio-vkusa.env` с владельцем `root:root` и правами `0600`.

Перед публикацией необходимо собрать приложение командой `npm ci && npm run build`, настроить production-значения, проверить уведомления, формы, медиа, редиректы и доступ к `/admin/`. Локальный `web/.env` на сервер не переносится.

## Статус миграции

Новая версия размещена на техническом адресе. Основной домен ещё ведёт на прежний сайт. Для переключения нужны настройки домена и TLS на принимающем сервере, а также проверка production-конфигурации, редиректов, уведомлений, форм, контента и юридических данных.
